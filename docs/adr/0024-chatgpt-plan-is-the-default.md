# 0023: The ChatGPT plan is the default; API keys are an optional extra

**Status:** accepted, 2026-10-25. Supersedes "Claude is the default model" in spec section 5, the Claude Haiku judge default in spec section 4 and ADR 0006, and the parts of ADR 0011 that made an Anthropic key the way in.

**Decision.** hamness must not depend on pay-per-token APIs. The default model is the user's ChatGPT plan, signed in with `hamness login openai`. API keys stay supported, but only for a model the user picks; setup and doctor never lead with them. Claude subscriptions can't be used outside Anthropic's own apps (ADR 0011), so Claude is reached only through an optional API key.

## What Pi offers (pi-ai and pi-coding-agent 1.3.0)

- **Two ChatGPT OAuth flows.** `openai-codex` ("OpenAI Codex (legacy)", `isSubscription: true`, base URL `https://chatgpt.com/backend-api`, api `openai-codex-responses`, OAuth only: no API-key auth at all). Its login is the Codex CLI's client (browser callback on `localhost:1455`, or a device code); the access token carries `chatgpt_account_id` and `chatgpt_plan_type` under the `https://api.openai.com/auth` claim, and requests fail with "Failed to extract accountId from token" without the account id. The other flow is the `openai` provider's "Sign in with ChatGPT" (a dynamic agent client for `api.openai.com`); its token lacks that claim, so it can't be copied to `openai-codex`, and some workspaces refuse it (`3p_delegated_access_policy_denied`).
- **Plan models** (`providers/data/openai-codex.json`): `gpt-6.1-sol` (500K context), `gpt-6-sol`, `gpt-6-astra`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5` (272K context each) and `gpt-5.3-codex-spark` (128K). All have 128K max output. The catalog lists API prices, but the plan bills none of them per token. Pi has no flag for which tiers serve which model.
- **Auth order.** A stored credential owns its provider; env keys are read only when nothing is stored. A runtime API key (what hamness sets from the key file or env) overrides a stored login, so hamness never sets one for a provider with a plan login.

## How hamness uses it

- `hamness login openai` (alias `chatgpt`) runs the `openai-codex` flow and stores it in `<dataDir>/pi/auth.json`. `hamness logout openai` removes it and an older `openai` login. An `openai` login stored before this ADR still counts as plan-billed, and doctor says to sign in again. A login refused with `3p_delegated_access_policy_denied` says why and what to try.
- **Default model order:** `HAMNESS_MODEL`, then `defaultModel` in `<dataDir>/config.json`, then the ChatGPT plan's model, then "not set up" (a clear message, no model). An API key alone never makes a model the default, so an `OPENAI_API_KEY` or `GEMINI_API_KEY` exported in the shell can't start a bill. Subagents use the session's model.
- **Model by tier (best-effort, observed live, not documented):** the tier is read locally from the Codex token's `chatgpt_plan_type` (never printed). Go: `gpt-5.6-terra` (on Go, `gpt-5.6-sol` and `gpt-5.5` stayed silent and `gpt-6.1-sol` was refused "not supported when using Codex with a ChatGPT account"). Plus, Pro, Team, Business, Enterprise, Edu: `gpt-6.1-sol` (on Team/Business, `gpt-6.1-sol`, `gpt-6-sol`, `gpt-5.6-sol` and `gpt-5.6-terra` all answered; Plus and Pro are assumed to match). Unknown tier: `gpt-5.6-terra`. The table is `PLAN_TIER_MODEL` in `src/agent/models.ts`; on Go the picker hides models the tier refused. When the backend refuses a model, the session switches to the tier's default and says so.
- **A session's stored model** with no key or login (a session last run on Claude) switches to the default on attach, resume, `/new` or `/fork`, with a notice: "Switched to … (plan): … has no key."
- **Visibility.** Doctor's model line says the model and how it is billed: "ChatGPT plan (subscription)" or "API (pay per token, from OPENAI_API_KEY)", plus "ChatGPT plan: Go · default gpt-5.6-terra" and which API keys exist (names only). The TUI header and `/status` show "· plan" or "· API"; the `/model` picker lists plan models first at "$0 (plan)" and API models with their key's source.
- **Stats.** Plan calls keep their tokens, store cost 0 and `model_calls.billing = 'plan'` (migration 8). `hamness stats`, the dashboard and `/status` show "$0 (plan)"; plan calls never count as unpriced. No API-equivalent dollar estimate is shown.
- **Judge.** Order: `safety.judge.model` (a plan model on the plan, an Anthropic model on its key), then the plan's `gpt-5.6-luna` at low thinking, then Claude Haiku only when the user chose an API model and has an Anthropic key; otherwise off. A plan call costs $0, so the daily cap is on calls: `safety.judge.dailyCalls`, default **500** a day (a busy day of undecided calls, small next to the plan's own limits). The $1 dollar budget still applies to an API judge. Any error, timeout, cut-off or answer that is not a strict verdict still means ask; plan judge calls are counted (and reserved while in flight) like API ones.

## Consequences

- A new user needs a ChatGPT plan (Go or higher) or must choose an API model on purpose. Claude users need an API key, as before.
- The tier table and the Go allowlist are guesses from live probes; revisit when Pi or OpenAI publish which tiers serve which Codex models.
- Pi marks `openai-codex` as legacy. If Pi drops it, the "Sign in with ChatGPT" flow is the fallback, and this ADR changes.
